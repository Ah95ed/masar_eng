# 📱 تطبيق Maxlond Engineer — دليل المشروع والمعمارية

تطبيق الهاتف واللوحي الميداني لمهندسي المواقع في شركة **Maxlond** للمقاولات العامة، مصمم خصيصاً لتسهيل متابعة المشاريع، إرسال التقارير اليومية، رفع الإيصالات والمرفقات، وتحديث تقدم المهام لحظياً باللغة العربية مع دعم كامل لاتجاه اليمين لليسار (RTL) وثيم Material 3.

## 🔄 2. إدارة الحالة (State Management)

تم اعتماد حزمة **`Provider`** كمعيار رئيسي لإدارة الحالة في التطبيق:

### لماذا Provider بدلاً من GetX؟

1. **الاستقرار والتوافق الرسمي:** الحزمة موصى بها من فريق Google وFlutter الرسمي وتعتمد على المكونات الأصلية لـ Flutter مثل `InheritedWidget` و `ChangeNotifier`.
2. **أمان الذاكرة ودورة الحياة (Lifecycle):** يتخلص Provider من الكائنات تلقائياً عند مغادرة الشاشة، بخلاف `GetX` الذي يحتفظ بكائناته في نطاق عام (Global Service Locator) مما قد يسبب تسريبات في الذاكرة (Memory Leaks) وأخطاء خفية يصعب تعقبها.
3. **فصل واضح للمسؤوليات:** يمنع تداخل منطق التوجيه (Routing) مع منطق الأعمال (Business Logic)، مما يجعل الكود نظيفاً وخاضعاً لاختبارات الوحدة (Unit Testing).

### منظومة الـ Providers في المشروع:

تم ربط جميع وظائف التطبيق (جلب البيانات، التحديث، إنشاء التقارير، رفع المرفقات، الإشعارات) بموفري حالة يرثون من `ChangeNotifier` لتفادي استخدام `setState` العشوائي وضمان التحديث التلقائي اللحظي:

1. **`AuthProvider`**:
   - إدارة حالة تسجيل الدخول واستعادة الجلسة والتحقق من دور المهندس وتسجيل الخروج.
2. **`DashboardProvider`**:
   - متابعة وتحديث إحصائيات لوحة المهندس (المهام المفتوحة، المنجزة، التقارير المنتظرة والمعتمدة).
3. **`TasksProvider`**:
   - جلب وتصفية المهام الميدانية حسب الحالة، وتحديث نسبة الإنجاز وحالة المهمة محلياً وعلى الخادم لحظياً مع إشعار لوحة التحكم بالتغيير.
4. **`ReportsProvider`**:
   - جلب قائمة التقارير، استعراض تفاصيل التقرير مع المصروفات والمرفقات، جلب المواقع، إنشاء التقرير اليومي، ورفع الإيصالات بصيغة Multipart مع التحديث التلقائي.
5. **`NotificationsProvider`**:
   - جلب التنبيهات، حساب عدد الإشعارات غير المقروءة، وتحديد التنبيه أو الكل كمقروء وتحديث الـ Badges فوراً.

### كيف تتكامل الشاشات بدون `setState`؟

- في شاشات العرض: نستخدم `context.watch<T>()` للاستماع لأي تغيير في البيانات وإعادة رسم الواجهة تلقائياً.
- في استدعاء العمليات (مثل حفظ مهمة أو رفع إيصال): نستخدم `context.read<T>()` لتنفيذ الأمر في الـ Provider، والذي يقوم بدوره بتحديث البيانات وإطلاق `notifyListeners()` لتحديث كافة الواجهات المرتبطة (مثل تحديث المهام ولوحة التحكم في آنٍ واحد).

## 🔒 3. الأمان وتخزين الجلسة (Security & Token Storage)

### التغلب على مشاكل Android 14+

- تم تجنب استخدام `flutter_secure_storage` نظراً لمشاكل الـ Keystore والتوافق مع نظام أندرويد 14 فما فوق.
- تم بناء كلاس **`SecureStorage`** مخصص يعتمد على:
  - تخزين المفتاح والـ Salt العشوائي لكل جهاز داخل `SharedPreferences`.
  - تشفير التوكن عبر مشتق مفتاح بواسطة **SHA-256** مع خوارزمية **XOR/AES** وتشفير المتجه المبدئي (IV).

### دورة تشغيل التطبيق الإلزامية:

في [lib/main.dart](lib/main.dart):

```dart
WidgetsFlutterBinding.ensureInitialized();
await SecureStorage.instance.init();       // 1. تهيئة التخزين المشفر
await SessionManager.instance.restore();    // 2. استرجاع الجلسة السابقة
runApp(MaxlondEngineerApp(api: api));      // 3. تشغيل التطبيق
```

## 🌐 4. التعامل مع الخادم والـ API

- **الرابط الأساسي للبوابة:** `https://vehiclegate.ghusun.net/api/engineer.php`
- **حظر الـ Cookies قطعيًا:** السيرفر يرفض أي طلب يحتوي على Cookie بجانب Bearer Token ويعيد `403 Forbidden`، لذا يقوم [EngineerApi](lib/services/engineer_api.dart) بمسح ترويسات الـ Cookie تلقائياً من جميع الطلبات.
- **معالجة 401 وإعادة المحاولة:** عند تلقي `401 Unauthorized`، يقوم الكود بإعادة محاولة الطلب تلقائياً لمرة واحدة باستخدام الترويسة البديلة `X-Auth-Token`. وفي حال الفشل مرة أخرى، تُمسح الجلسة ويُعاد المستخدم لشاشة الدخول.
- **حصر الدور:** يقبل التطبيق فقط المستخدمين الذين يحملون الدور `role == "engineer"`.

## 🔔 5. نظام الإشعارات والتحديث اللحظي (Realtime & Background Notifications)

تم بناء منظومة إشعارات متكاملة وشاملة تغطي كافة حالات عمل التطبيق (أثناء التشغيل Foreground، في الخلفية Background، وبعد الإغلاق الكامل Terminated) على بيئتي **Windows** و **Android**:

- 🍞 **إشعار تفاعلي عائم داخل التطبيق (`InAppNotificationToast`):**
  - بدلاً من الاكتفاء باللون أو عداد الشارة، يظهر كارت إشعار عائم فوري أعلى الشاشة (Top Toast / Banner).
  - مصمم بدقة لدعم شاشات الويندوز والهواتف مع حركات انزلاق وظهور سلسة (`Slide & Fade Transition`).
  - يتضمن أيقونة ملونة ولون مميز حسب النوع (اعتماد، رفض، مهمة جديدة، تعميم)، عنوان الإشعار، نص الرسالة، وزر إغلاق سريع.
  - النقر المباشر على التوست ينقل المهندس فورياً إلى تفاصيل المهمة أو التقرير المعني ويعلّم الإشعار كمقروء.
  - دعم اهتزاز اللمس الخفيف (`HapticFeedback`) على الهواتف.

- 📲 **إشعارات النظام المحلية الأصلية (`Local Notifications`):**
  - استخدام حزمة `flutter_local_notifications` لإصدار إشعارات نظام حقيقية:
    - **على Android:** تظهر في شريط الإشعارات العلوي للنظام بصوت واهتزاز وقناة مخصصة (`masar_engineer_channel`) ذات أولوية قصوى (`Importance.max`).
    - **على Windows:** تظهر كإشعار توست أصلي لسطح المكتب داخل مركز الإجراءات (Windows Action Center).
  - النقر على الإشعار من خارج التطبيق يفتح التطبيق ويوجه المهندس تلقائياً للشاشة المعنية.

- ⚙️ **الفحص الدوري في الخلفية وعند إغلاق التطبيق (`WorkManager` - Terminated / Background):**
  - تسجيل مهمة خلفية دورية على نظام أندرويد عبر `Workmanager` تعمل كل **15 دقيقة** حتى لو كان التطبيق مغلقاً تماماً (`Terminated`).
  - نقطة الدخول `@pragma('vm:entry-point') notificationCallbackDispatcher`:
    1. تقرأ التوكن المشفر المخزن بأمان.
    2. تفحص الخادم لجلب الإشعارات الجديدة غير المقروءة.
    3. تقارن معرفات الإشعارات وتصدر إشعار نظام محلي لكل تنبيه جديد.
    4. تحدث مؤشر آخر إشعار تمت مشاهدته في `SharedPreferences` منعاً للتكرار.

- ⚡ **تحديث شلالي فوري (`Cascade Refresh`):** وصول إشعار بمهمة يُحدّث شاشة المهام، ووصول إشعار باعتماد/رفض تقرير يُحدّث شاشة التقارير ولوحة التحكم فوراً.
- 🔴 **شارة العداد المباشرة (`NotificationBadge`):** عداد أحمر تفاعلي في الـ AppBar والقائمة الجانبية.
- 🔄 **تحديث يدوي صريح (`Manual Refresh`):** دعم السحب للأسفل (`Pull-to-Refresh`) وزر التحديث في شريط العنوان.

## 💻📱 6. التصميم المتكيف بين الشاشات (Adaptive Responsive Design)

تم بناء نظام تجاوب متكامل وتخصيص جذري بين تجربة الهاتف وتجربة الويندوز / التابلت عبر `lib/core/responsive.dart`:

### 🚫 1. إلغاء شريط التنقل السفلي نهائياً (No Bottom Bar)
- تم حذف شريط التنقل السفلي (`BottomNavigationBar` / `NavigationBar` / `BottomSheets`) بالكامل في جميع الشاشات (الهاتف والكمبيوتر).

### 🖥️ 2. شاشات الويندوز / الديسكتوب والتابلت (Windows / Desktop / Tablet >= 700px):
- **شريط جانبي ثابت على اليمين (Persistent Right Sidebar):** قائمة أقسام ثابتة دائماً على يمين الشاشة بعرض 260px تتضمن:
  - بطاقة المهندس المسجل وشعار الشركة.
  - أقسام التنقل مع مؤشرات التحديد وعداد الإشعارات غير المقروءة.
  - مؤشر حالة الاتصال بالخادم.
  - زر تسجيل الخروج السريع.
- **عرض البيانات عبر شبكات تفاعلية (`GridView`):**
  - استعراض بطاقات المهام والتقارير عبر شبكات متعددة الأعمدة (2-4 أعمدة حسب العرض) بدلاً من القوائم الطولية الممتدة.
  - بطاقات غنية بمؤشرات التقدم، حالة الاعتماد، وتفاصيل الموقع.
- **تناسق حقول الإدخال والـ Edit Text:**
  - تقسيم النماذج إلى صفوف أفقية متوازنة (2-3 حقول في الصف) ومحددة بعرض مناسب (`maxWidth`) لمنع التمدد المشوه.
  - جدول المصروفات الميدانية يعرض الحقول أفقياً في صف متكامل (البند + الفئة + الكمية + السعر + الحذف).
  - ثيم Material 3 موحد مع حواف ناعمة وخلفيات مريحة للأعين.

### 📱 3. شاشات الهاتف الذكي (Mobile < 700px):
- **قائمة جانبية منزلقة (`Drawer`):** يتم فتح الأقسام بسلاسة عبر أيقونة القائمة في الـ AppBar دون إشغال حيز الشاشة الصغيرة.
- **عرض القوائم الرأسية (`ListView`):** بطاقات لمس مريحة متتالية رأسياً ومناسبة للتصفح باليد الواحدة.
- **نماذج عمودية سهلة اللمس:** حقول إدخال رأسية ومتباعدة تسهل الكتابة على لوحة المفاتيح الافتراضية.
